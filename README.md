# 아트로드 웹사이트

기존 Next.js App Router + TypeScript 프로젝트를 이어 구현한 소개 랜딩페이지, 공지사항 게시판, 활동 아카이브와 아티스트 소개 페이지입니다. 단체소개서 26쪽 전체를 확인하고 원본의 인디고·청회색과 실제 공연 사진을 바탕으로 구성했습니다. 클라이언트 검토용으로 정적 배포할 수 있으며, 검색 엔진 수집은 비활성화되어 있습니다.

## 실행 및 검증

Node.js 20.9 이상. 기존 의존성과 실행 규칙을 유지합니다.

```bash
npm run dev
```

기본 주소는 `http://localhost:8134`입니다. 다른 프로젝트의 8123 포트는 사용하지 않습니다. 로컬 인터페이스로 제한하려면 다음 명령을 사용합니다.

```bash
npm run dev -- --hostname 127.0.0.1
```

```bash
npm run typecheck
npm run lint
npm run build
```

## 수정 위치

- `content/site.ts`: 소개, 사업, 아티스트 분야, 문의 이메일. 홈의 활동·선정 이력은 아카이브 데이터에서 가져옵니다.
- `content/archive.ts`: 활동 상세, 확인된 사실, 사진·캡션, 선정 이력과 출처 쪽수
- `content/notices.ts`: 공지 제목·날짜·요약·본문
- `content/artists.ts`: 소개서에 실린 아티스트 네 명의 분야와 대표 활동
- `content/partners.ts`: 소개서 25쪽의 주요 협력 파트너 로고 여덟 개
- `content/types.ts`: 이미지 공통 타입
- `app/page.tsx`: 홈 섹션 구성
- `app/archive/page.tsx`, `app/archive/[slug]/page.tsx`: 아카이브 목록과 활동 상세
- `app/artists/page.tsx`: 소속 및 협업 아티스트 소개
- `app/notices/page.tsx`, `app/notices/[slug]/page.tsx`: 공지 목록과 상세
- `app/globals.css`: 인디고 디자인, 한 코너 아치, 반응형 스타일, 모션 감소 대응
- `app/layout.tsx`: 공통 헤더·푸터·본문 바로가기와 메타데이터. 클라이언트 검토 중에는 `noindex, nofollow`
- `components/`: 헤더·푸터, 섹션 제목, 링크 버튼, 사진, 태그라인, 현재 위치 표시, 아카이브 미리보기
- `public/assets/`: 실제 활동 사진 11장, 아티스트 사진 4장, 아트로드 로고 1장과 협력 파트너 로고 8장의 WebP 사본. 전체 페이지나 PDF는 포함하지 않습니다.
- `reference/docs/`: 비공개 원본. 웹에서 참조하지 않고 Git·빌드 추적에서 제외합니다.
- `docs/content-map.md`: 콘텐츠와 사진의 출처, 미확인 자료
- `docs/artist-review.md`: 개인 프로필 공개 검토 목록. 웹에서 가져오지 않습니다.
- `docs/verification.md`, `docs/qa/`: 실제 검증 결과와 화면 캡처

## 활동 아카이브

- 목록: `/archive`. 내비게이션의 ‘아카이브’와 홈의 ‘전체 아카이브 보기’로 연결합니다.
- 상세: `/archive/dogok-picnic`, `/archive/oasis-in-street`, `/archive/starlight-live`, `/archive/gangnam-happy-concert`, `/archive/gangnam-cultural-support`.
- 사진이 있는 공연·활동 기록 4개와 선정 이력 4건에는 서로 겹치는 항목이 있습니다. 고유 상세 기록은 5개이며 공연 8건으로 집계하지 않습니다.
- `content/archive.ts`의 `archiveEntries`에 고유 slug, 제목, 분류, 기간 표기, 요약, 본문, 사실 목록, 사진·캡션, 출처 쪽수를 추가합니다. 선정 기록이 있는 경우에만 `selection`을 추가합니다.
- `gallery`가 있는 기록은 공연 현장 목록에 표시하고, `selection`은 연도별·최신순으로 정렬합니다. 사진 없는 기록에 대체 공연 사진을 붙이지 않습니다.
- 홈의 대표 활동은 `content/site.ts`에서 선택합니다. 홈과 아카이브가 제목·설명·이미지·선정 정보를 공유합니다.
- 목록과 상세는 빌드 시 정적으로 생성됩니다. 데이터 변경 후 다시 빌드하면 반영됩니다. 웹 관리자·로그인·게시글 입력 폼은 없습니다.

## 공지사항

- 목록: `/notices`
- 첫 글: `/notices/website-open`, ‘아트로드 웹사이트를 오픈했습니다!’
- 작성일: 2026-11-05, 사용자가 요청한 날짜 기준
- `content/notices.ts`에서 고유 slug, 제목, YYYY-MM-DD 날짜, 분류, 작성자, 요약과 문단 배열을 관리합니다. 최신 날짜순으로 표시하며 빌드 시 정적 페이지를 생성합니다.

## 콘텐츠와 이미지 원칙

소개서에 있는 사실만 사용하며 선정 월을 실제 공연 날짜나 완료 실적으로 바꾸지 않습니다. 공연 횟수도 합산하지 않습니다. 행사명이 확인되지 않는 현장 사진은 특정 사업에 임의 연결하지 않습니다.

사진은 PDF 내 개별 이미지를 추출해 WebP로 변환하고 원본 비율을 유지합니다. 합성·생성·인물 변경은 없습니다. 원본 해상도 한계가 있으므로 운영 전 고해상도 사진 교체를 권장합니다.

새 아티스트 페이지에는 소개서에 실린 이름·분야·대표 활동과 개인별 사진을 간결하게 표시합니다. 사진의 외부 게시 범위는 운영 전 확인합니다. 개인 연락처와 학력은 제외합니다. 문의는 원본 26쪽의 `artroad91@gmail.com`으로 연결하는 표준 `mailto:` 방식이며 외부 전송·서버 저장·문의 폼은 없습니다.

## 운영 전 확인

활동 사진과 협력 파트너 로고의 웹 게시 범위, 아티스트 프로필 사진 및 상세 경력의 게시 허용 범위, 문의 이메일 운영 여부를 확인합니다. 운영 주소가 정해지면 canonical·공유 이미지의 절대 URL과 검색 허용 설정을 마무리합니다. 원본 PDF나 참고 문서를 배포 폴더에 복사하지 않습니다. 자동 배포 설정은 추가하지 않았습니다.

## 클라이언트 검토용 배포

- 정적 빌드: `npm run build:static` (`out/` 출력)
- Sites 배포 설정: `.openai/hosting.json`
- GitHub에는 사이트 소스와 사용 이미지 사본만 포함합니다. `reference/` 원본과 `docs/` 내부 검토 자료는 Git과 배포에서 제외됩니다.
- 홈의 아티스트 섹션과 내비게이션에서 별도 소개 페이지로 이동합니다. 현재 수정 사항은 로컬에만 반영하며 추가 배포하지 않습니다.
